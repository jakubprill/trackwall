When the line shows

  • For a task, and for each repo of a change, since each starts from that repo's main. Not for a session, which works on the checked-out branch.
  • When main lacks commits of origin/main as of the last fetch (1), or when the server check found newer ones (2). Up to date: no line at all.
  • Also when another branch is checked out: the line is about main, where the task starts.

What "Sync main" does

What "Sync all" does, for this one repo: a fetch, then a fast-forward of main when nothing is in its way. It never touches the checked-out branch or uncommitted changes. When main cannot move (4), the line says why and names the repo's Shell tab, where to merge (the form has no link to a repo's tab yet).

Never in the way

"Create task" stays enabled in every state: starting from the older code can be what the user wants, for example to reproduce a bug in the released version.

Rejected

  • A sync before every task by itself: a fetch on every start waits for the network and runs the repo's own git configuration without a click on Sync.
  • Starting the task from origin/main while main stays behind: the task's base would differ from the main the user sees and reviews against.
  • Holding the start until main is synced (above).
