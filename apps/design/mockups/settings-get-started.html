Settings: get started

Today Trackwall needs one setting to work, the projects folder, and has thirty-two sections of settings that all look equally important. What stops a new user is mostly outside Settings: Copilot CLI is not installed or does not trust the folder, a company proxy, git without a sign-in in the container. Those are found only by the doctor, at the bottom of the last category. Nothing ever says "you are ready".

Variant A · the other categories · to build

Every setting is one folded row, from the left edge

Settings no longer sits in the middle of a wide window: it starts next to the activity bar. A setting shows its name, one line on what it does and its value now; a dot marks a value you changed. A click opens the form with the full text and a link to its page. So there is no separate "Advanced" tab to hunt through: everything is one screen, and nothing is open until asked. The same folded row is the pattern for the long forms of the other views later.

Variant B · not proposed

Profiles you choose

A first screen asks where Trackwall runs and fills the settings from the answer. It adds a question whose answer Trackwall already has, a wrong pick sets things up wrong, and a profile cannot fix what is outside Settings: the proxy, the sign-ins, the trusted folder. What a profile would fill in is one path, which the folder suggestion already does.

Variant C · the smallest step

Only the layout and the texts

Settings from the left edge, folded rows as in variant A, shorter texts, and no "Get started". Settings gets calm, but a new user still has to know that the doctor exists.

What "minimum" really isOne setting: the projects folder. Everything else in Settings has a default that works. The rest of the minimum is outside Settings: Copilot CLI installed and signed in, and on a company network the proxy and its certificate. In a container also git's name and its sign-in to the repo host.
One click instead of a manual"Use this folder" saves the folder Trackwall found. "Trust this folder" writes the folder into Copilot CLI's trusted folders, which today is a JSON edit by hand; it is the one place where Trackwall would change Copilot CLI's own file, only on your click.
TextsOne sentence per setting, written as what it does for you. The long explanation and "Saved as … in workspace.yaml" move into the opened row; the file names stay in Settings › Files.
What it does not fixThe dev container still needs its devcontainer.json and a rebuild before Trackwall runs at all. The page starts helping from the moment Trackwall answers.
