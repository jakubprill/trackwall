Remove a repo

A repo added to Trackwall (cloned or found in the projects folder) can be removed from the repo's own header, not only through the supervisor. Removing moves the folder out of the projects folder into .trackwall/removed, as the supervisor's removal does; nothing is deleted. The user confirms by typing the repo's name, and the removal waits while anything of Trackwall works in the repo.

1. The header gets “Remove…”

The button sits last in the header, in the destructive colour, and only opens the panel below; nothing happens on one click.

2. Nothing runs in the repo: type its name to remove it

The panel says where the folder goes and that nothing is deleted, names what the repo still holds that is not on the server, and enables “Remove repo” only when the typed text equals the repo's name.

3. Something still works in the repo: the removal waits

A session in the repo, an agent task (its worktree and branch belong to the repo) or a running mise task blocks it, as for the supervisor's removal; a service or terminal the daemon names when the user presses the button. The panel lists each as in “In this repo”, a button to where it is; the field and the button stay off until the list is empty. Trackwall never ends a task for the user here: a task's branch may hold work not pushed anywhere.

4. Variant not recommended: also delete from disk

A box that deletes the folder for good instead of moving it. It loses unpushed commits, stashes and files outside git, and on Windows a file held open can leave half a folder behind. Recommended: leave deleting to the user, who sees the removed folder in the file manager.
