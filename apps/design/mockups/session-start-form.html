Before

Repo list, prompt, a worktree checkbox, an approvals checkbox and three paragraphs of description. A model only on a proposal.

1. Two things on top

Where and what. Repo tags next to the list, because the pills depend on them.

2. Pills instead of checkboxes

  • Each shows its state, a click changes it.
  • A pill appears only when it makes sense: “Java navigation” for the java tag, approvals only with a worktree, almost nothing in the projects folder.
  • A yellow dot means an option with a risk (no approvals, no worktree).
  • The cost next to the pill (RAM, time) instead of a paragraph.

3. Descriptions behind “?”

Only warnings stay, when something is at risk: two sessions in one working copy, the jdtls limit.

4. Defaults

From Settings, then the last choice in this repo. Usually only the prompt and Ctrl+Enter.

5. Command preview

The grey line at the bottom says what Trackwall actually starts. Open: keep it in the product, or only in a developer mode.

6. Supervisor proposal

The same pills, filled in by the supervisor in propose_task; you change them before the start.
