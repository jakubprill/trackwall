Task notices: one strip in every layout

Proposal for the Sessions view. What sits above a task's terminal today (mise config warning, shared files, messages, summary, verification, merge request, mise tasks) becomes one row of chips. Layout 1 can open it in place; a grid tile shows it as an overlay, so the terminal never changes size.

One line, always

The strip is one row high. Chips that do not fit collapse into “+2”.

Warnings stand out

Warnings are yellow chips and come first. Clicking a chip opens the details at that section.

Stays folded

“Details” is remembered per task. A new warning does not unfold it, so the terminal does not jump mid-turn.

Badge in the header

Tile 1 and 2: a yellow “⚠ n” when there are warnings. Tile 3: a grey “ⓘ” when there is only information (summary, verification passed, a mise task running). No notices, no badge.

Overlay, not a row

Clicking the badge lays the notices over the top of the terminal, like the close confirmation does. The PTY keeps its size. Esc, ✕ or a click on the terminal closes it.

A new warning shows once

Tile 2: a warning that appears while you watch the grid shows as a one-line banner over the terminal until you press Show or ✕. After that only the badge stays.

How it would be built

  • One list of notices per task, built once in a hook and used by the strip, the details, the tile badge and the overlay, so both layouts always say the same thing.
  • The sections that load their own data today (shared files, mise config, mise tasks) get that data from the same hook, so the strip knows they exist.
  • Tests: unit tests for which notices a task has and their order; the small-screen E2E checks the folded strip in layout 1 and the overlay on a grid tile.
