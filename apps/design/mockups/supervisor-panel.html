Supervisor panel: before and the proposal

A mockup of the right panel on Home. On top, screenshots of the version at the time (the fake Copilot of the E2E tests); below, the same panel in four states after simplifying it.

What was wrong

  • The header held up to five buttons of similar weight: Start my day, Resume, New (or Start supervisor / Start again) and an icon without a label. Nothing said how they differ.
  • Start again did not repeat what you had started. It always began a new, empty conversation without a sync or a day report. It showed instead of Resume when Copilot had not yet saved the conversation (for example Stop right after Start my day). Hence the impression that after End and Start again something else started.
  • Start my day was always highlighted as the main action, also at noon, when you only want to go back to the conversation.
  • The speech-bubble icon (chat instead of terminal) applied only to the next start and had no label. A click changed nothing visible.
  • After Stop the panel looked almost as while working: the old screen, the state cut to “stopp…”, the start buttons back in the header. It did not say “stopped” plainly.
  • The message field: Send and Stop stacked next to a field of a fixed two-line height, so the buttons did not stick to the field. After the session ended the field stayed, greyed out, with a bright Send button.
  • Under the header an extra line with the Copilot window title (“GitHub Copilot”, “check the build”) looked like one more state.

Proposal: three states, one main button

The header says only what state the supervisor is in, and has one action: Stop, while it works. Every start moves into a card in the panel body, each with one sentence on what it does. There is always one main action: Start my day in the morning, Continue during the day.

The main button rule: Start my day when it has not run today or there is no conversation to continue; otherwise Continue. The daemon already stores the last day start with its time, so the UI computes the rule alone. Only two small things would be new on the daemon side: remembering whether Start my day began the conversation (the “by Start my day” note), and the repo counts of the sync step (without them the step says only “Synced the repos”). Numbers and times in the mockup are examples.
