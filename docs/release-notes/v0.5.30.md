Trackwall 0.5.30 shows what backs a task's change above its diff, lets an agent say its task is done so you close it in one click, watches the health of a dev container and backs up and restores the work that lives only there, opens on Sessions with what is left before a first session right above the form, and brings your shells back after a restart.

## What's new

- **Evidence above a task's diff.** A task's "Changes" tab opens with an "Evidence" card: one row per fact that backs the change (your approval of the plan, the reproduction test and Trackwall's check of it, the verification, the rules check, the models), each with whose word it is. Green means Trackwall checked it on the files as they are now, red means a check speaks against the change, yellow means something is still open or was checked on an earlier version of the changes. See [Agent tasks](https://jakubprill.github.io/trackwall/features/tasks).
- **Ready to close.** A task's agent can say that nothing is left for it to do, and the task reads "Ready to close" with "Close task" and "Keep open". Home's "Needs you" lists every such task with "Close all". The agent never closes a task itself, and any new work for it takes the mark back. See [Agent tasks](https://jakubprill.github.io/trackwall/features/tasks).
- **Container health.** In a dev container, "Settings > Diagnostics > Container health" shows memory, processors, processes and free disk against the container's limits, the day's memory, every process killed for lack of memory and every daemon restart, and warns when a state lasts. The warnings also show under "Container" in Home's "Needs you" and as a count on Home's icon in every view, and agents can read them, so a build killed with exit code 137 is not taken for a bug in the code. See [Container health](https://jakubprill.github.io/trackwall/features/container-health).
- **Restore a work backup, and back up on a schedule.** "Restore from a backup…" lists, repo by repo, what bringing a backup into a new container would do before anything changes, and never overwrites your work: a branch that went another way keeps its place and the backup's commit gets a `restored/` branch. While the desktop app is connected to Trackwall in a dev container, it downloads a backup every 4 hours and keeps the newest 14. See [Container work backup](https://jakubprill.github.io/trackwall/features/work-backup).
- **Publish the container's ports instead of forwarding them.** The Dev Container Feature has a `publish` option, so Docker's published ports reach Trackwall in the container directly, as fast as a local connection, with or without a VS Code window open. See [Dev container](https://jakubprill.github.io/trackwall/guide/dev-container).
- **Trackwall opens on Sessions.** The main window opens on Sessions, and the view bar runs Sessions (Ctrl+1), Repos, Overview, Plan, Flow and Home (Ctrl+6). A window opened on Home keeps it. See [Navigation and windows](https://jakubprill.github.io/trackwall/features/navigation-and-windows).
- **A first session from one view.** On a new install, the steps of "Get started" that are not done show in a card above the Sessions form, each with what settles it right there, until the first session starts. Before a projects folder is set, the card is all the view shows, instead of a form that could only fail. The question about Copilot CLI trusting the folder shows only while it does not, and "Routines" shows from the first routine on. See [Get started](https://jakubprill.github.io/trackwall/features/get-started).
- **The supervisor panel starts folded** in a new window, so the first task's terminal gets the room. One click on its strip or Alt+0 pins it open, and a layout you chose before stays. See [Supervisor](https://jakubprill.github.io/trackwall/features/supervisor).
- **Shells come back after a restart.** Each shell that ran when Trackwall stopped opens again as a new shell in the same folder, with a dim line saying so. A shell you closed stays closed. See [Shell](https://jakubprill.github.io/trackwall/features/shell).
- **Work in several repos is one change by default.** The supervisor and other sessions propose work across repos as one change, made by one agent in one conversation, with each repo's part still reviewed, verified and merged on its own; a task per repo only when you ask for it. See [Changes](https://jakubprill.github.io/trackwall/features/changes).
- **Plan shares the width.** Plan's list and the selected item share the width half and half, with a bar to drag between them, narrow rows keep their titles, and "Read full width" shows an item in one reading column. See [Plan](https://jakubprill.github.io/trackwall/features/plan).
- **Copilot CLI's version, with the way to fix it.** The doctor and the window's strip name the Copilot CLI version Trackwall is tested with and, in a dev container, say where to install it: with mise or in the container's image, depending on where the running one comes from. The dev container guide pins that version.
- **The doctor warns when Copilot CLI's sandbox on Windows cannot start git**, and says how to give the sandbox access to it. See [Doctor](https://jakubprill.github.io/trackwall/features/doctor).

## Fixed

- **The one session of a change verifies every part.** In a change across several repos, the agent could verify and run mise tasks and services only in the lead repo; the others were refused, and the agent fell back to running tests by hand.
- **An agent waiting for another one no longer waits forever** once you had looked at the other agent's finished turn, and a message on its way counts as work, so the waiting agent reads fresh results.
- **A new session's terminal is transparent from the start**, not an opaque box until the layout changed.
- **Windows shells show the restart line** like the other systems.

## Moving from 0.5.29

Click "Update and restart" (or "Update after their turn" while agents work) when Trackwall offers 0.5.30, or install it by hand ([Update by hand](https://jakubprill.github.io/trackwall/guide/install#update)). Your data in `~/.trackwall` stays, and the sessions that were running come back after the restart. Trackwall now opens on Sessions, and Home's shortcut is Ctrl+6. Download `trackwall-0.5.30.vsix` from the release to update the VS Code extension.

## Known limitations

- Sessions run Copilot CLI only, and it has to be installed and signed in.
- The app is not signed: on Windows download it with `gh` or `curl.exe`, or run `Unblock-File` on the zip; on macOS remove the quarantine with `xattr`.
- A proxy that signs you in with your Windows account or replaces certificates can stop the update download; the manual update still works then.
- macOS on Apple Silicon only.
- The VS Code extension is not in the Marketplace: download its `.vsix` from the release and install it by hand after each update.
- "Pull" only fast-forwards: a branch that has diverged from the one it tracks is left for you to merge or rebase in a shell.
