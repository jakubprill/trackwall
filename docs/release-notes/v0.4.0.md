Trackwall 0.4.0 makes agent tasks something you can run, check and send back for fixes without leaving the app, adds a supervisor session above all the others, and is the first version that updates itself.

## What's new

- **Updates from the app.** From this version on, Trackwall checks GitHub Releases and offers "Update and restart" when a newer version is out. The update is checked against the release signature before it is installed. See [App updates](https://jakubprill.github.io/trackwall/features/updates).
- **Supervisor.** One Copilot CLI session in the projects folder, pinned on the right of every view (Alt+0). It hands work out as task proposals and checks the results; everything it proposes still waits for your approval. See [Supervisor](https://jakubprill.github.io/trackwall/features/supervisor).
- **Task proposals together.** The proposals of one session are one entry in "Sessions": read each one, tick several and start them at once, or reject one with a reason the agent gets back.
- **Task worktrees ready to run.** Files listed in `.worktreeinclude` (such as `.env`) are copied into every new task's worktree, each task gets its own port (41000–41999, in `SERVER_PORT` and `PORT`), and mise tasks and services can run from the task's worktree next to the ones from the repo root. A changed mise config in a worktree waits for "Trust this config".
- **Verify.** One button in the task panel runs the task's mise task `test` and shows one verdict with the failed tests and the first errors from the log. Agents get the same through `verify_task`.
- **Review comments.** Comment on lines in a task's "Changes" tab and send them to its agent as one review.
- **Approvals outside the terminal.** The tray panel and Home show what an agent asks to approve, with Copilot CLI's own options, and answer it with one click. `toolPermissions` in `workspace.yaml` allows or denies tools for every new session. See [Approvals outside the terminal](https://jakubprill.github.io/trackwall/features/approvals).
- **More for agents over MCP.** `get_task_changes` (a task's diff), `get_test_results` (JUnit reports), `get_review_comments` and `verify_task`. Every session is told which Trackwall started it and where the documentation is.
- **Faster with many repos.** A commit, checkout or pull shows up in "Repos" and "Overview" within about a second, and missing repo cards are computed in the background after the start.
- **Session terminals.** `trackwall://` links that Copilot CLI breaks over rows or shows as named links open on Ctrl/Cmd+click, and a text selection stays until it is copied. A task without a session can be ended from its grid tile or list row.
- **Documentation site.** Every feature has its page at [jakubprill.github.io/trackwall](https://jakubprill.github.io/trackwall/), with an `llms.txt` for agents.

## Moving from 0.3.0

0.3.0 has no updater, so this one move is manual: quit Trackwall from the tray ("Quit") and install 0.4.0 the same way as before ([Install](https://jakubprill.github.io/trackwall/guide/install)). Your data in `~/.trackwall` stays. From 0.4.0 on, new versions install themselves after you click "Update and restart".

Tasks created in 0.3.0 get a task port at the first start, and their mise config shows as "not been trusted yet" once.

## Known limitations

- Sessions run Copilot CLI only, and it has to be installed and signed in.
- The app is not signed: on Windows download it with `gh` or `curl.exe`, or run `Unblock-File` on the zip; on macOS remove the quarantine with `xattr`.
- A proxy that signs you in with your Windows account or replaces certificates can stop the update download; the manual update still works then.
- macOS on Apple Silicon only.
