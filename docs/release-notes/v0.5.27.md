Trackwall 0.5.27 hands a merge request's review threads to the task's agent, finds folders your antivirus scans, gives every session one clear state in short words, keeps a session working while its agent waits for background agents, and sends task sessions much shorter instructions, so a task spends fewer tokens on every model call.

## What's new

- **Review threads from a merge request go to the task's agent.** Under a task's open merge request, "Read threads" lists the threads nobody has resolved yet on GitLab or GitHub, each with its file and line, author and a link. "Send to agent" hands the ones you tick to the task's agent, which fixes the code on the same branch and tells you the branch needs a push. Trackwall writes nothing to the repo host: replying and resolving stay there. See [Agent tasks](https://jakubprill.github.io/trackwall/features/tasks).
- **The doctor finds folders an antivirus scans.** "Settings > Diagnostics > Doctor" has an "Antivirus scanning" row. It times writing small files in your projects folder, Trackwall's state folder and Maven's and Gradle's caches, and names the folders that are much slower than the others, with the paths to exclude from real-time scanning. See [Doctor](https://jakubprill.github.io/trackwall/features/doctor).
- **One state per session, in short words.** A session shows one state from a short list everywhere: "Working", "Needs you: answer", "Needs you: approval", "Needs you: plan", "Ready for review", "Idle", "Error", "Finished", "Stopped", "Paused", "May be stuck", "Not responding". "Ready for review" replaces "idle" together with the "In review" mark, and "Verify again" replaces "Verify outdated". A state Trackwall only guessed from the screen has a hollow dot instead of the word "probably". The usage moves to the end of the name line, in short, such as "3.4k cr". See [Sessions](https://jakubprill.github.io/trackwall/features/sessions).
- **Shorter instructions for task sessions.** A task's agent no longer gets the guide to every Trackwall tool, only its own role; a task you start yourself in one repo gets a short role of about 1.7 KB instead of 14 KB. The instructions go with every model call, so a task uses noticeably fewer tokens. The supervisor and other sessions keep the full guide. See [Session instructions](https://jakubprill.github.io/trackwall/features/session-instructions).

## Fixed

- **A session whose agent waits for background agents stays "Working".** Before, Trackwall took the agent's pause for the end of its work: it said the session needed you, ended the task's round and could hand your review to a subagent. Now the work ends when Copilot CLI's turn after the background agents ends, and only the main agent gets what waits for the session.
- **A task that only answers goes back to review.** When a task's agent answered a review or a message without changing anything and without reporting again, the task stayed at work. It is now ready for review again.
- **No two tasks on the same repo in one task tree.** A task can no longer propose a task in a repo that another branch of its tree already works in; the agent is told which task covers it.
- **Text stays inside its frame in the Sessions list.** The waiting time no longer runs over the usage, the "Next waiting" button's label wraps instead of running out of the button on Windows, a task's header keeps its state and usage clear of its buttons on a small screen, and a group's colour stripe stays visible next to a selected main session.
- **A fresh install starts without an error** and no longer backs up its own new files on the second start as if an older Trackwall had written them.

## Moving from 0.5.26

Click "Update and restart" (or "Update after their turn" while agents work) when Trackwall offers 0.5.27, or install it by hand ([Update by hand](https://jakubprill.github.io/trackwall/guide/install#update)). Your data in `~/.trackwall` stays, and the sessions that were running come back after the restart. Download `trackwall-0.5.27.vsix` from the release to update the VS Code extension, which shows the new state words too.

## Known limitations

- Sessions run Copilot CLI only, and it has to be installed and signed in.
- The app is not signed: on Windows download it with `gh` or `curl.exe`, or run `Unblock-File` on the zip; on macOS remove the quarantine with `xattr`.
- A proxy that signs you in with your Windows account or replaces certificates can stop the update download; the manual update still works then.
- macOS on Apple Silicon only.
- The VS Code extension is not in the Marketplace: download its `.vsix` from the release and install it by hand after each update.
- The antivirus check compares folders with each other: a scanner that slows every folder alike gives no warning, only the times.
- Reading merge request threads needs `glab` or `gh` signed in to the repo host, and reads at most 100 threads.
