Trackwall 0.5.26 explains a task's change before you read it, refreshes a task from `main`, remembers "Always allow" for a repo's tasks, opens anything with Ctrl+K, shows how long a session has waited for you, keeps a copy of your state before an update, stops a task at its token budget and fills the merge request description with Trackwall's evidence.

## What's new

- **Explain this diff.** A task's "Changes" tab has an "Explanation" section: Copilot CLI reads the task's prompt and its whole change and writes a summary, one point per part of the change, and the places worth a closer look. See [Automatic review](https://jakubprill.github.io/trackwall/features/auto-review).
- **Refresh from main.** When others merge to the default branch while a task runs, "Refresh from main" at the top of "Changes" merges the newest `main` into the task's branch as one merge commit. When the merge would conflict, nothing changes and the files that would conflict are named. See [Agent tasks](https://jakubprill.github.io/trackwall/features/tasks).
- **Always allow in a task's approval.** A task's approval may offer "Always allow `npm test` in this repo's tasks": from then on every task of that repo runs that command without asking, also the ones already running, until you remove it in Settings. See [Approvals](https://jakubprill.github.io/trackwall/features/approvals).
- **A command palette on Ctrl+K** (⌘K on macOS; Ctrl+Shift+K in a terminal). Type a few letters of a session, task, repo, view or Settings category and press Enter. It also starts a new session, opens the next session waiting for you and switches the theme. See [Navigation and windows](https://jakubprill.github.io/trackwall/features/navigation-and-windows).
- **How long a session has waited for you.** After a minute, a waiting session says for how long, such as "asking for approval · 12 min", in the list, on its tile, on Home and in the tray panel. See [Sessions](https://jakubprill.github.io/trackwall/features/sessions).
- **A warning before too many tasks run at once.** When starting a task would make more tasks run at once than your computer is set for, the New session form and the task proposals say so; you can still start. See [Agent tasks](https://jakubprill.github.io/trackwall/features/tasks).
- **A copy of your state before an update.** Before another version reads `~/.trackwall`, Trackwall copies its state into `~/.trackwall/state-backups` (the last ten are kept), and going back to the older version puts the matching copy back, so your tasks, rounds and verdicts match again. See [Updates](https://jakubprill.github.io/trackwall/features/updates).
- **A token budget per task.** Set "Token budget per task" in "Settings > Agents", such as `2M` or `500k`. A task's header shows how much of it the task used, and when it reaches the budget Trackwall stops the task as Stop does; Resume gives it the budget again. See [Agent tasks](https://jakubprill.github.io/trackwall/features/tasks).
- **A fuller merge request draft.** "Open merge request" now fills in the agent's summary, its steps for checking the change and "Evidence from Trackwall", what Trackwall itself saw of the change. When the repo has its own default template (GitLab's `Default.md` or GitHub's `pull_request_template.md`), the description is that template filled in. See [Agent tasks](https://jakubprill.github.io/trackwall/features/tasks).
- **Your own prefix for task branches.** When your repo host accepts only branches such as `feature/...`, add `taskBranchPrefix: feature/` to `~/.trackwall/workspace.yaml`. See [Agent tasks](https://jakubprill.github.io/trackwall/features/tasks).
- **The sandbox and the supervisor in Settings.** "Settings > Agents > Sandbox" chooses which tasks run their commands in Copilot CLI's sandbox, and "Supervisor changes code" lets the supervisor run commands and edit files itself, asking for approval like any other session. See [Approvals](https://jakubprill.github.io/trackwall/features/approvals) and [Supervisor](https://jakubprill.github.io/trackwall/features/supervisor).
- **The VS Code extension in every release.** `trackwall-0.5.26.vsix` now comes with the release, next to the app's archives, so you no longer build it from the source. See [VS Code extension](https://jakubprill.github.io/trackwall/features/vscode-extension).

## Fixed

- **A failed model call no longer looks like work.** From Copilot CLI 1.0.109 a prompt to a model your account does not offer ends without an answer. The session now shows an error, waits for you, and a strip under its header says "The model call failed" with Copilot CLI's message, instead of staying "working".
- **The automatic reviewer reads its own diff.** A review or rules check could be refused access to the files Trackwall wrote for it; it now reads them, and a review that was refused and found nothing ends as failed instead of as a clean result.
- **A link to an unknown session or task** (one that ended, or from Trackwall running in a dev container) now says so and leaves the selection as it was, instead of opening another one.
- **The VS Code extension in a dev container** ignores a "Trackwall: State Folder" from your computer that does not exist in the container.
- **A clearer message when the app cannot reach the daemon**: it tells a port that nothing listens on apart from a forwarded port that does not answer.
- **A sandboxed task on macOS no longer hangs at Copilot CLI's certificate authority question.** The task waits for you with a notification, and its buttons offer only "Continue without installing".
- **The sandbox in a dev container on a Mac with Colima.** The [dev container guide](https://jakubprill.github.io/trackwall/guide/dev-container) now adds `--device /dev/net/tun`, without which every command of a sandboxed task failed, and the doctor says when that device is missing instead of showing the sandbox as on. Signing in to Copilot CLI in the container uses `copilot login --device-code`.

## Moving from 0.5.25

Click "Update and restart" (or "Update after their turn" while agents work) when Trackwall offers 0.5.26, or install it by hand ([Update by hand](https://jakubprill.github.io/trackwall/guide/install#update)). Your data in `~/.trackwall` stays, and the sessions that were running come back after the restart. With the sandbox in a dev container, add `"--device", "/dev/net/tun"` to `runArgs` and rebuild the container. Download `trackwall-0.5.26.vsix` from the release to update the VS Code extension.

## Known limitations

- Sessions run Copilot CLI only, and it has to be installed and signed in.
- The app is not signed: on Windows download it with `gh` or `curl.exe`, or run `Unblock-File` on the zip; on macOS remove the quarantine with `xattr`.
- A proxy that signs you in with your Windows account or replaces certificates can stop the update download; the manual update still works then.
- macOS on Apple Silicon only.
- The VS Code extension is not in the Marketplace: download its `.vsix` from the release and install it by hand after each update.
- On macOS, git in the sandbox cannot read `~/.gitconfig` unless you add it to `readonlyPaths` in Copilot CLI's sandbox settings.
- Only a repo's default merge request template is used.
- "Always allow" is not offered for a PowerShell command on Windows, in the supervisor or in a session in the repo itself.
- "Refresh from main" needs the repo's remote and is refused while the agent is in the middle of a turn or the working copy has uncommitted changes.
- Going back to 0.5.25 or older: those versions make no state copies, so a file they cannot read is set aside as `<file>.newer-<time>` in `~/.trackwall`.
