Trackwall 0.5.13 shows how far a task's API change reaches and hands each reached repo a task, lets one task hand its work to another, tells the supervisor what is going on with every message, counts waiting agents in a browser tab, and explains in the documentation why Trackwall exists and how it works.

## What's new

- **Impact of a task.** A task's new "Impact" tab lists the endpoints its commits add, remove or change, and the repos that call them, ring by ring, up to three rings out. "Hand off" on a reached repo starts a task there with a prompt that says what changed and where that repo calls it; "Show on Overview" lights the rings on the connection graph. See [Impact of a task](https://jakubprill.github.io/trackwall/features/impact).
- **One task hands its work to another.** A task proposed by another task is told which task handed it the work, on which branch and at which commit, and is asked to look again when that task commits more. Agents get two new tools for it: `get_changed_endpoints` (the endpoints a task's commits change and who calls them) and `get_handoff`. See [Main session and task proposals](https://jakubprill.github.io/trackwall/features/main-session).
- **The supervisor knows what is going on.** Every message you write to the supervisor carries a short, fresh list of the work under way: every task with who started it and what its agent is doing, the proposals waiting for you and the sessions you opened yourself. "What is waiting for me?" gets an answer at once, and the supervisor does not propose work you already started by hand. See [Supervisor](https://jakubprill.github.io/trackwall/features/supervisor).
- **Notifications in the browser.** Trackwall opened in a browser tab, for example from a dev container, counts the sessions and proposals waiting for you in the tab's title, and after "Turn on notifications" shows a browser notification when an agent needs you while you work elsewhere. See [Notifications in the browser](https://jakubprill.github.io/trackwall/features/browser-notifications).
- **Documentation.** New guide pages: why Trackwall exists, how it works (the window, the daemon and the agents), the key flows as diagrams, the security model and what Trackwall does not do yet. See [Why Trackwall](https://jakubprill.github.io/trackwall/guide/why-trackwall).

## Fixed

- **`find_endpoint` lists each caller once.** A client that reaches a repo through two targets, for example a gateway and a direct address, no longer shows as two callers.

## Moving from 0.5.12

Click "Update and restart" (or "Update after their turn" while agents work) when Trackwall offers 0.5.13, or install it by hand ([Update by hand](https://jakubprill.github.io/trackwall/guide/install#update)). Your data in `~/.trackwall` stays, and the sessions that were running come back after the restart. If you skip 0.5.11, take the two one-time steps from its release note: "Push to this remote" in "Settings > Workspace" for a local config store with a remote, and pointing antivirus or backup rules at the new `.trackwall` folder.

## Known limitations

- Sessions run Copilot CLI only, and it has to be installed and signed in.
- The app is not signed: on Windows download it with `gh` or `curl.exe`, or run `Unblock-File` on the zip; on macOS remove the quarantine with `xattr`.
- A proxy that signs you in with your Windows account or replaces certificates can stop the update download; the manual update still works then.
- macOS on Apple Silicon only.
- "Impact" compares only committed HTTP endpoints; messages, events and GraphQL are not compared, and repos with Kotlin code show what they reach as "maybe".
