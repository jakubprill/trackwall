Trackwall 0.5.29 pulls a repo's checked-out branch from its header and puts aside the changes in the way, trusts the projects folder for Copilot CLI in one click, adds a troubleshooting guide, and shows less at once in Settings, a task's header and the repo list.

## What's new

- **Pull from the repo header.** When a repo's checked-out branch is behind the branch it tracks, the Upstream tile in its header has "Pull" with the number of commits. It fetches, syncs the default branch as "Sync all" does and fast-forwards the checked-out branch; it never merges, rebases or pushes. When it cannot pull, the tile says why and offers a way on. See [Repos](https://jakubprill.github.io/trackwall/features/repos).
- **Put aside changes in the way.** When uncommitted changes stop a pull or a batch sync, "Put aside and pull…" (or "Put aside and sync…" in the Batch command) lists the files that would leave the working folder, moves them into a git stash and goes on. The "Changes" tab lists what Trackwall put aside, with "Restore" and "Delete…". See [Repos](https://jakubprill.github.io/trackwall/features/repos) and [Batch command](https://jakubprill.github.io/trackwall/features/batch-command).
- **Trust folder.** "Get started" and the New session form have a "Trust folder" button that adds the projects folder to Copilot CLI's trusted folders, so Copilot CLI no longer asks "Do you trust the files in this folder?" in every repo and task. See [Get started](https://jakubprill.github.io/trackwall/features/get-started).
- **Troubleshooting.** A new [Troubleshooting](https://jakubprill.github.io/trackwall/guide/troubleshooting) guide lists common setup problems with what they mean and how to fix them: SmartScreen and Gatekeeper, the window's daemon start errors, Copilot CLI not found or not signed in, trusted folders, a company proxy and certificates, git access to repo hosts, mise and the sandbox. It also says how to install Copilot CLI and sign in to it outside a dev container.
- **VS Code from a repo session.** A session in a repo's own folder (without "Own worktree") has a "VS Code" button in its header that opens the repo's folder.
- **Get started stands out.** In the list of Settings categories, "Get started" is framed and says how many steps are left ("3 steps to do", "All set"); Settings opens on it while a step is open. "Settings" and "Reports" are set apart as groups.
- **A shorter task header.** A task's header shows Verify, VS Code, "More" and Stop; "More" holds "Copy included files", "Change model", "Hand to supervisor" and "Pause", by name. See [Agent tasks](https://jakubprill.github.io/trackwall/features/tasks).
- **A warning about a newer Copilot CLI.** When sessions start a Copilot CLI newer than the version Trackwall is tested with, a strip above the views says so, with "Diagnostics" and "Hide", and the doctor's "Copilot CLI" line asks you to check it. Sessions usually still work; if one shows a wrong state, install the tested version again until a Trackwall tested with yours comes out. See [Doctor](https://jakubprill.github.io/trackwall/features/doctor).
- **A shorter repo list header.** Above the repo list stand "Add", "…" (More) and "Sync all"; the tag filter is folded and still shows the tags you picked. The rest (the projects folder, Shell, Batch command, Change the projects folder, Refresh the repo list) is in "…". See [Repos](https://jakubprill.github.io/trackwall/features/repos).

## Fixed

- **The Batch command starts with nothing ticked.** It opened with every step and every repo ticked, so one habitual click on "Run" synced, installed and built the whole folder. Steps and repos now each have "All" and "None", and "Run" waits until you tick at least one step and one repo. See [Batch command](https://jakubprill.github.io/trackwall/features/batch-command).
- **Merge request threads go to the agent as you read them.** "Read threads" ticks nothing at first and shows every note that would go to the agent, in full. "Send to agent" sends exactly the notes you saw; when a picked thread changed on the repo host since you read it, nothing is sent and the panel asks you to read the threads again. See [Agent tasks](https://jakubprill.github.io/trackwall/features/tasks).
- **Closing a shell is instant.** "Close" in a Shell tab hid the shell only after about five seconds, and a new shell waited for the old one to end. Now the shell goes at once and a new one opens right away. See [Shell](https://jakubprill.github.io/trackwall/features/shell).

## Moving from 0.5.28

Click "Update and restart" (or "Update after their turn" while agents work) when Trackwall offers 0.5.29, or install it by hand ([Update by hand](https://jakubprill.github.io/trackwall/guide/install#update)). Your data in `~/.trackwall` stays, and the sessions that were running come back after the restart. Download `trackwall-0.5.29.vsix` from the release to update the VS Code extension.

## Known limitations

- Sessions run Copilot CLI only, and it has to be installed and signed in.
- The app is not signed: on Windows download it with `gh` or `curl.exe`, or run `Unblock-File` on the zip; on macOS remove the quarantine with `xattr`.
- A proxy that signs you in with your Windows account or replaces certificates can stop the update download; the manual update still works then.
- macOS on Apple Silicon only.
- The VS Code extension is not in the Marketplace: download its `.vsix` from the release and install it by hand after each update.
- "Pull" only fast-forwards: a branch that has diverged from the one it tracks is left for you to merge or rebase in a shell.
