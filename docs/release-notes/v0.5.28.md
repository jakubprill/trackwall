Trackwall 0.5.28 makes a change across several repos one agent in one conversation, shows a new user what is left before a first session, folds Settings, the New session form and a repo's card down to what you need, closes nine ways a sandboxed task could make Trackwall's git run a program, and fixes "Create change in N repos", which failed every time in 0.5.27.

## What's new

- **A change across several repos runs in one session.** A change still has a task per repo, each with its own changes, verification and merge request, but one agent makes the whole change in one conversation, in a folder that holds every repo's worktree. A review, a message or Resume on any part reaches that agent, and its one report hands every part over for review. In our measurements this costs a third to a seventh of one agent per repo. See [Changes](https://jakubprill.github.io/trackwall/features/changes).
- **Get started.** The first Settings category lists what stands before a first session, in the order to do it: the projects folder, Git, Copilot CLI and the network, then what is recommended. When nothing needed is left, it says "Ready" and offers "Start a session". See [Get started](https://jakubprill.github.io/trackwall/features/get-started).
- **Settings as folded rows.** Every setting in Workspace, Agents and App is one row with its name, one sentence and its value now; a dot marks a value you changed. A click opens the full form. Settings sections that load no longer jump when their data arrives.
- **A shorter New session form.** Templates, the extra options and the note about trusting the folder are folded; "More options" names every option that differs from a plain start, and opens by itself when one does. See [Task templates](https://jakubprill.github.io/trackwall/features/task-templates).
- **A tidier repo card.** Each kind of fact on a repo's "Card" tab is one folded row with its count, and the kinds the repo has none of share one row, "Not found in this repo". See [Repo card](https://jakubprill.github.io/trackwall/features/repo-card).
- **Fewer tokens per task.** A task's agent no longer runs the whole test suite itself next to `verify_task`, and `get_repo` returns only the first 4,000 characters of a README.

## Fixed

- **A change in several repos starts again.** "Create change in N repos" failed with `Unrecognized key: "kind"` under the button, and no task started.
- **Safer sandboxed tasks.** A task in Copilot CLI's sandbox could write git settings or hooks into its repo that made Trackwall's own git, which runs outside the sandbox, run a program as you or send a fetch with your credentials to another host. Trackwall now closes nine such ways.
- **Approvals in a short terminal on Copilot CLI 1.0.112.** An approval drawn in a terminal of some 16 rows or fewer showed "Needs you: approval" without buttons. Trackwall now reads it and offers its selected option.
- **Home with many repos no longer freezes the window.** With about a hundred labelled repos, Home could hang the whole window a moment after it opened.
- **Fewer git processes for an open task**, about half while nothing happens, so the "Changes" tab answers sooner on a machine that inspects every process start.
- **A cut file preview ends on a whole character**, a file with a tab in its name opens, and a repo git cannot read says so instead of "the repo has no commits yet".

## Moving from 0.5.27

Click "Update and restart" (or "Update after their turn" while agents work) when Trackwall offers 0.5.28, or install it by hand ([Update by hand](https://jakubprill.github.io/trackwall/guide/install#update)). Your data in `~/.trackwall` stays, and the sessions that were running come back after the restart. Download `trackwall-0.5.28.vsix` from the release to update the VS Code extension.

## Known limitations

- Sessions run Copilot CLI only, and it has to be installed and signed in.
- The app is not signed: on Windows download it with `gh` or `curl.exe`, or run `Unblock-File` on the zip; on macOS remove the quarantine with `xattr`.
- A proxy that signs you in with your Windows account or replaces certificates can stop the update download; the manual update still works then.
- macOS on Apple Silicon only.
- The VS Code extension is not in the Marketplace: download its `.vsix` from the release and install it by hand after each update.
