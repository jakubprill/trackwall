Trackwall 0.5.33 shows a task's failed tests in a Tests tab of their own and hands them to the agent, runs the mise tasks of a monorepo's packages, lets you remove a repo from the Repos view and works with Copilot CLI 1.0.115.

## What's new

- **A Tests tab in every task.** Next to "Changes", with a red count of the failed tests on the tab, it lists the tests of every JUnit report in the task's worktree, from Verify and from the agent's own runs: only the failed ones by default, by test class and without pages; "Skipped" and "All" show the rest, and "Filter by name" narrows the list. A note says when the task's files changed after the reports were written, with "Verify again". See [Agent tasks](https://jakubprill.github.io/trackwall/features/tasks).
- **Failed tests open to their stack trace.** A failed test in a task's Verification (and in the Tests tab) opens to what it expected and what it got, the start of its stack trace with library frames folded, and your own frames as links that open the line in VS Code. "Fix this" hands one test to the agent, "Fix failed tests" all of them, as a review would. See [Agent tasks](https://jakubprill.github.io/trackwall/features/tasks).
- **mise tasks of monorepo packages.** A folder below the repo root with its own `mise.toml` gets its own box in the repo's "mise tasks" tab, and Run starts its tasks in that folder, with its `[env]` and tools; mise's experimental mode is not needed. Agents see and run them as `//<package>:<task>`. A package mise does not trust yet has its own "Trust" button. See [mise tasks](https://jakubprill.github.io/trackwall/features/mise-tasks).
- **Remove a repo.** "Remove…" in a repo's header in the Repos view takes the repo off the list once you type its name: its folder moves into `.trackwall/removed` in the projects folder, and nothing is deleted. The panel names what the folder holds that is not on the server and what still runs in the repo. See [Repos](https://jakubprill.github.io/trackwall/features/repos).
- **Copilot CLI 1.0.115.** Trackwall is now tested with Copilot CLI 1.0.115. Trackwall's own read-only tools run without asking, as before; read-only tools of your own MCP servers now ask, as Copilot CLI 1.0.115 intends.

## Fixed

- **A container's start time after the host slept.** In "Settings > Diagnostics > Container health", a container under Docker on WSL or macOS could show that it started hours after Trackwall's daemon inside it. Its start is now never later than the daemon's, and the "Processes" tile says that its count includes threads.
- **"No" on Copilot CLI's folder trust question** ends the session as `Done`, no longer as `Error` that needs you.

## Moving from 0.5.32

Click "Update and restart" (or "Update after their turn" while agents work) when Trackwall offers 0.5.33, or install it by hand ([Update by hand](https://jakubprill.github.io/trackwall/guide/install#update)). Your data in `~/.trackwall` stays, and the sessions that were running come back after the restart. Download `trackwall-0.5.33.vsix` from the release to update the VS Code extension. Update Copilot CLI to 1.0.115 (`npm i -g @github/copilot@1.0.115`): Trackwall warns when another version runs. A task that was running in a repo with mise packages asks once for its mise config to be trusted again, since the packages' configs are now checked too.

## Known limitations

- Sessions run Copilot CLI only, and it has to be installed and signed in. Trackwall is tested with Copilot CLI 1.0.115 and warns when a newer one runs.
- The app is not signed: on Windows download it with `gh` or `curl.exe`, or run `Unblock-File` on the zip; on macOS remove the quarantine with `xattr`.
- A proxy that signs you in with your Windows account or replaces certificates can stop the update download; the manual update still works then.
- macOS on Apple Silicon only.
- The VS Code extension is not in the Marketplace: download its `.vsix` from the release and install it by hand after each update.
- "Pull" only fast-forwards: a branch that has diverged from the one it tracks is left for you to merge or rebase in a shell.
