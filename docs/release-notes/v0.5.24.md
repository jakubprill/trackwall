Trackwall 0.5.24 adds Flow, a wall of all agent work for a second monitor, lets a task start from a Java stack trace and checks its reproduction test, lets a task plan first, shows the model a session really runs on, brings sessions into VS Code, and can run Copilot CLI's sandbox in a dev container.

## What's new

- **Flow.** A new view (Ctrl+6 or ⌘6) puts every task, session and task proposal on one wall, a row per group (a Plan project, a change across repos, the supervisor, a session with its proposals) and a column per state: Working, Waits for you, In review, Stuck and Idle. Each card shows how long it has been there, the longest wait on top. Open it in its own window for a second monitor. See [Flow](https://jakubprill.github.io/trackwall/features/flow).
- **A task from a Java stack trace.** The New task form has a folded **Stack trace** field. Trackwall finds the trace's frames among the repo's files, marks the root cause and asks the agent to write a failing test first, then fix the code. The agent names its reproduction test in its result. See [Agent tasks](https://jakubprill.github.io/trackwall/features/tasks).
- **Check the reproduction test yourself.** **Check it** under the reproduction test runs it in a separate copy of the repo, without the fix and with it, and says whether it really reproduced the error. The task's own worktree is not touched. See [Agent tasks](https://jakubprill.github.io/trackwall/features/tasks).
- **Plan first.** A task in "Chat (preview)" can start with **Plan first**: its agent reads the code and answers with a plan without changing files. Reply to change the plan, then press **Approve plan** to let it work. See [Agent tasks](https://jakubprill.github.io/trackwall/features/tasks).
- **The model a session really runs on.** When Copilot CLI runs a session on another model than the one you asked for (it falls back silently when your account does not offer the model), a strip says "Runs on X, not Y" and points to the Model button. A task's terminal session now shows its usage too. See [Copilot CLI sessions](https://jakubprill.github.io/trackwall/features/sessions).
- **The task journal keeps the model and usage.** An ended task's record now says which model did the work and what it used, for later comparisons.
- **Sessions in VS Code.** A Trackwall extension for VS Code shows in the status bar how many sessions wait for you and lists them in a side bar; a click opens the session in Trackwall. Turn it on in "Settings > App > VS Code extension" and install the `.vsix`. See [VS Code extension](https://jakubprill.github.io/trackwall/features/vscode-extension).
- **Copilot CLI's sandbox in a dev container.** A dev container set up as the guide describes runs tasks without approvals in the sandbox, so their commands no longer see the other repos or your sign-ins. In a container that is not set up, the doctor now warns that such tasks have its full access. See [Run in a dev container](https://jakubprill.github.io/trackwall/guide/dev-container).
- **Drop files into a container.** With Trackwall in a dev container, a file dropped on a session terminal or a shell is copied into the container (up to 256 MB) and its path is pasted in. See [Copilot CLI sessions](https://jakubprill.github.io/trackwall/features/sessions).
- **Java navigation explained to the agent.** A session with Java navigation is told that `lsp` waits for jdtls's import at the first start and that an empty answer during the import says nothing about the code. See [Java navigation](https://jakubprill.github.io/trackwall/features/java-navigation).
- **Tested with Copilot CLI 1.0.107.** With a custom provider, the Model fields no longer suggest `auto`, which that version refuses.

## Fixed

- **Prompts reach Copilot CLI 1.0.107 again.** Trackwall now reads its framed input box, so reviews, read requests and grouping prompts go in, and the supervisor has a state again.
- **Board cards drag in the desktop app.** Dragging a card on the Plan board works on macOS and Windows, and Alt+← and Alt+→ work right after a click.
- **A removed task frees its board item.** Removing the last task on an item in progress puts the item back in Ready.
- **No repeated strips.** A stopped session no longer fills its panel with the same "environment from mise changed" strip.
- **No false mise gap.** A repo without its own mise config no longer shows "Problems in the mise config".
- **Settings fit the system.** Path examples match the system the path is on, and the container update button stays inside its card.
- **State survives future updates.** Trackwall's state files now carry a format version, so a later update can migrate them instead of setting them aside.

## Moving from 0.5.23

Click "Update and restart" (or "Update after their turn" while agents work) when Trackwall offers 0.5.24, or install it by hand ([Update by hand](https://jakubprill.github.io/trackwall/guide/install#update)). Your data in `~/.trackwall` stays, and the sessions that were running come back after the restart. To use the sandbox in a dev container, follow the guide's sandbox section and rebuild the container.

## Known limitations

- Sessions run Copilot CLI only, and it has to be installed and signed in.
- The app is not signed: on Windows download it with `gh` or `curl.exe`, or run `Unblock-File` on the zip; on macOS remove the quarantine with `xattr`.
- A proxy that signs you in with your Windows account or replaces certificates can stop the update download; the manual update still works then.
- macOS on Apple Silicon only.
- The VS Code extension is not in the Marketplace: build the `.vsix` from the source.
- Plan first works only for a task in Chat (preview), and Chat has no Java navigation for tasks.
