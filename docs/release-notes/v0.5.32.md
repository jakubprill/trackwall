Trackwall 0.5.32 keeps Trackwall's and Copilot CLI's settings in the workspace store if you want, brings them back into a new computer or container with a look at each change first, and keeps the New session form's buttons under the mouse.

## What's new

- **Settings in the workspace store.** "Settings > Workspace > Workspace store" has "Keep Trackwall and Copilot CLI settings in the store" (off by default). While it is on, the store also keeps `workspace.yaml` and Copilot CLI's `settings.json`, `copilot-instructions.md` and `mcp-config.json`, with secrets masked; Copilot CLI's sign-in stays out. See [Local config backup](https://jakubprill.github.io/trackwall/features/local-config).
- **Restore settings from the store.** "Restore settings from the store…" lists each setting and Copilot CLI file that differs from this computer, with its lines before and after, and restores the ones you tick. Settings that decide what agents may run or read, where they work or push, or what they spend are listed apart and start unticked, since an agent can commit to the store. The projects folder and the store's own settings never come back. See [Local config backup](https://jakubprill.github.io/trackwall/features/local-config).

## Fixed

- **The New session form's buttons stay under the mouse.** Turning "Own worktree" on or off moved "Own worktree" and "More options" by a row, since "Stack trace" came and went above them. It now stands under them.
- **A group of the workspace store that is off no longer leaves the store by itself.** A new container with an empty `workspace.yaml` would have committed the removal of Plan and knowledge within a minute; now only unticking it in Settings takes its folders out.
- **Removing a folder no longer fails when the folder is already gone**, as happened on macOS when git wrote into it while it was being removed.

## Moving from 0.5.31

Click "Update and restart" (or "Update after their turn" while agents work) when Trackwall offers 0.5.32, or install it by hand ([Update by hand](https://jakubprill.github.io/trackwall/guide/install#update)). Your data in `~/.trackwall` stays, and the sessions that were running come back after the restart. Download `trackwall-0.5.32.vsix` from the release to update the VS Code extension.

## Known limitations

- Sessions run Copilot CLI only, and it has to be installed and signed in. Trackwall is tested with Copilot CLI 1.0.114 and warns when a newer one runs; 1.0.115 is not supported yet.
- The app is not signed: on Windows download it with `gh` or `curl.exe`, or run `Unblock-File` on the zip; on macOS remove the quarantine with `xattr`.
- A proxy that signs you in with your Windows account or replaces certificates can stop the update download; the manual update still works then.
- macOS on Apple Silicon only.
- The VS Code extension is not in the Marketplace: download its `.vsix` from the release and install it by hand after each update.
- "Pull" only fast-forwards: a branch that has diverged from the one it tracks is left for you to merge or rebase in a shell.
