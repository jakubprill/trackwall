Trackwall 0.5.17 makes Trackwall in a dev container start with the container every time and lets the window update it.

## Before you start

If Trackwall runs in a dev container, rebuild the container once ("Dev Containers: Rebuild Container" in VS Code) so that it gets the Feature's new entrypoint. Keep Trackwall's settings, such as `TRACKWALL_HOME` and a proxy, in `containerEnv`, not `remoteEnv`: Trackwall now starts before VS Code connects.

## What's new

- **Update Trackwall in the container from the window.** When "Start the dev container and connect" finds another version of Trackwall in the container, the window names both versions and offers **Update Trackwall in the container**. It installs the app's version there and connects once it answers; if the new version does not start, the container goes back to the one it had and the window says so. See [Dev container](https://jakubprill.github.io/trackwall/guide/dev-container).

## Fixed

- **Trackwall starts with every start of the dev container**, also after `docker restart` or a start from Docker or Rancher Desktop without VS Code. Before, it ran only when VS Code started the container. A Docker Compose dev container started with `docker compose up` still does not start it. See [Dev container](https://jakubprill.github.io/trackwall/guide/dev-container).
- **A task's journal lists only the agent's own commits**, without the commits Trackwall makes after each round, and a task's commits no longer make Trackwall read the main checkout's git status again after every turn.

## Moving from 0.5.16

Click "Update and restart" (or "Update after their turn" while agents work) when Trackwall offers 0.5.17, or install it by hand ([Update by hand](https://jakubprill.github.io/trackwall/guide/install#update)). Your data in `~/.trackwall` stays, and the sessions that were running come back after the restart. In a dev container, read "Before you start" above. If you skipped 0.5.15, read its "Before you start" about the sandbox on Linux.

## Known limitations

- Sessions run Copilot CLI only, and it has to be installed and signed in.
- The app is not signed: on Windows download it with `gh` or `curl.exe`, or run `Unblock-File` on the zip; on macOS remove the quarantine with `xattr`.
- A proxy that signs you in with your Windows account or replaces certificates can stop the update download; the manual update still works then.
- macOS on Apple Silicon only.
- Chat (preview) has no Java navigation for tasks, and a running task cannot switch between the terminal and Chat.
