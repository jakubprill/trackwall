Trackwall 0.5.15 reviews a task's changes automatically, keeps tasks without approvals in Copilot CLI's sandbox, lets agents propose a change across several repos and links its merge requests, copies to the clipboard from a session in a container, and smooths several rough edges of the dev container.

## Before you start

- **The sandbox on Linux.** On Linux an agent task started with "No approvals" now runs its shell commands in Copilot CLI's sandbox, which needs `bubblewrap` (with `slirp4netns`, `iproute2` and `iptables`). Where it cannot run, Trackwall refuses to start such a task and says what to install, and the doctor shows the same. Set `sandbox.tasks: off` to start them without it. In a container, and on macOS and Windows, the sandbox stays off until you turn it on. See [Approvals](https://jakubprill.github.io/trackwall/features/approvals).

## What's new

- **Automatic review.** A task's "Changes" tab has an "Automatic review" section: **Review** runs Copilot CLI's own `/review` on the task's changes and lists its findings with severity, file and line. **Add to review** turns a finding into a draft comment on its line, which reaches the agent only when you send the review. "Review a task's changes when its agent reports its result" in "Settings > Agents" starts it without a click. See [Automatic review](https://jakubprill.github.io/trackwall/features/auto-review).
- **Tasks without approvals in the sandbox.** Each shell command of such a task, and every build or script it starts, can write only in the task's worktree, and cannot read your other repos or credential folders such as `~/.ssh`. The task's header says it runs in the sandbox. See [Approvals](https://jakubprill.github.io/trackwall/features/approvals).
- **Agents propose a change across several repos.** The supervisor or a main session can propose one change for several repos at once. It arrives as one card in "Sessions" with every repo in merge order and the agent's note for each; you can edit the prompt and notes and untick repos before you start it. See [Changes across several repos](https://jakubprill.github.io/trackwall/features/changes).
- **A change's merge requests together.** Each part's task panel has a "Change" section listing every part with its merge request and state, pointing out the merge order, and pushing all parts at once. The New session form and a proposed change hint the merge order from the connection graph and workspace knowledge, for example "orders-api calls payments, so payments is usually merged first". See [Changes across several repos](https://jakubprill.github.io/trackwall/features/changes).
- **Copy to the clipboard from a session in a container.** `/copy` in a session terminal copies the agent's last answer also when Trackwall runs in a container. When an agent is asked to copy something, a strip under the session's header shows what it wants to copy, and the clipboard changes only when you click **Copy**. See [Sessions](https://jakubprill.github.io/trackwall/features/sessions).
- **Session profile changes are visible.** A running session that started with another session profile says so in its panel, with **Restart to apply**, and its grid tile's key badge turns yellow. The doctor gets a "Model provider of the session profile" row that says whether the provider of your profile accepts connections, without showing its address or key. See [mise environment](https://jakubprill.github.io/trackwall/features/mise-environment) and [Doctor](https://jakubprill.github.io/trackwall/features/doctor).
- **More in the conversation view (preview).** A tool row shows the files the agent works on, a file change opens as a coloured diff with the lines it adds and removes, an approval to change a file shows that change before you allow it, and "Thought" above an answer opens the agent's reasoning when the model gives it. "Agent" and "Plan" next to the turn line switch the agent's mode (Autopilot stays in the terminal and `/autopilot`), a meter shows how much of the model's context the conversation uses and turns yellow from 75%, a slash at the start of a message lists the agent's commands, a pasted screenshot or the paperclip attaches images and text files such as a log (up to five, 10 MiB together), and work handed to a subagent shows as a "Subagent" row with what it was asked and its answer. See [Supervisor](https://jakubprill.github.io/trackwall/features/supervisor).
- **Other MCP clients.** "Connect Copilot CLI" now explains how to add Trackwall to any MCP client and what such an agent can and cannot do with it. See [Connect Copilot CLI](https://jakubprill.github.io/trackwall/guide/connect-copilot-cli).
- **Zoomable screenshots in the documentation.** A click on a screenshot opens it as large as the window allows.

## Fixed

- **Copilot CLI's folder trust question.** A session started in a folder Copilot CLI does not trust used to show "state unknown". It now waits for you like an approval, with "Yes" and "Yes, and remember this folder" answerable from Trackwall.
- **Fewer false connections in the graph.** When apps of several repos run on the same `localhost` port, such as Spring's 8080, a client on that port is connected only to the repos whose endpoints match its calls.
- **The dev container.**
  - A start that waits can be cancelled.
  - A container VS Code will not reuse is named.
  - When the daemon in the container restarts with a new token, the window asks for the new address within two seconds instead of showing "invalid token" in every view.
  - The Trackwall Feature runs the container with an init process, so stopped sessions leave no orphan processes.
  - The guide's example keeps the container running when its last VS Code window closes.
- **Sessions in a repo's root keep its checkout.** Their instructions now tell the agent not to switch the root's branch, which every task's graph, Impact and the repo's service depend on.

## Moving from 0.5.14

Click "Update and restart" (or "Update after their turn" while agents work) when Trackwall offers 0.5.15, or install it by hand ([Update by hand](https://jakubprill.github.io/trackwall/guide/install#update)). Your data in `~/.trackwall` stays, and the sessions that were running come back after the restart. On Linux, read "Before you start" above.

## Known limitations

- Sessions run Copilot CLI only, and it has to be installed and signed in.
- The app is not signed: on Windows download it with `gh` or `curl.exe`, or run `Unblock-File` on the zip; on macOS remove the quarantine with `xattr`.
- A proxy that signs you in with your Windows account or replaces certificates can stop the update download; the manual update still works then.
- macOS on Apple Silicon only.
- Chat (preview) has no Java navigation for tasks, and a running task cannot switch between the terminal and Chat.
