Trackwall 0.5.12 lets a task's service take the repo's port, runs tasks in the conversation view, starts sessions with a session profile, starts the dev container from the desktop app and needs much less git and CPU while it waits.

## Fixed

- **Less git on a slow machine.** Home and Repos no longer run `git status` in every repo every 30 seconds. A repo's last status is reused while nothing in its git folder changed, so a commit, checkout, fetch or staging shows at the next refresh, and an edit in the files shows within about a minute on a slow machine.
- **Less CPU while nothing happens.** An open window no longer makes every session be checked twice as often, and `workspace.yaml` is read again only when it changed.
- **Subtasks stay with their task.** Work a task's session proposed stays with the task after Resume, `resume_task` or a restart: the task's new session can still send it messages, gets its updates, and the subtask stays under the task in "Sessions".
- **Session tokens.** The files Copilot CLI reads for a session's MCP server and hooks now hold only that session's own token, not the token of the whole daemon.
- **Logs of ended tasks.** Ending a task removes the logs of the mise tasks run in its worktree. At start, Trackwall also removes logs left behind by tasks it no longer knows.

## What's new

- **A task's service on the repo's port.** While the repo's service runs, a task's panel offers "Run on the repo's port". The task's copy of the service then takes the repo's port, so a frontend, another service or the browser reaches the task's code. "Give the port back" starts the repo's service again. See [Services](https://jakubprill.github.io/trackwall/features/services).
- **Tasks in the conversation view (preview).** A "Chat (preview)" pill on the New session form and on a proposal runs the task as a conversation instead of a terminal. Resume goes on with the same conversation, and reviews and messages arrive as the next message. Java navigation still needs a terminal. See [Tasks](https://jakubprill.github.io/trackwall/features/tasks).
- **Session profile.** "Settings > Agents > Session profile" takes a mise environment name, for example `byok`. Every agent session then starts with that profile's mise config on top of the usual ones, for instance to point Copilot CLI at another model provider, without restarting Trackwall. See [mise environment](https://jakubprill.github.io/trackwall/features/mise-environment).
- **Copy included files into a running task.** "Copy included files", in the task panel and in the tile's task menu, copies what `.worktreeinclude` names into a task's existing worktree, with the same rules as when the worktree is created. See [Tasks](https://jakubprill.github.io/trackwall/features/tasks).
- **Start the dev container from the desktop app.** In "Settings > App > Daemon in a container", save the folder that holds `.devcontainer` once. "Start the dev container and connect" then starts it if needed, reads the token itself and connects, also after the daemon in it restarts. "Open in VS Code" opens the full Dev Container window when the container's config names its folder. See [Run in a dev container](https://jakubprill.github.io/trackwall/guide/dev-container).
- **Filters for agents' log tools.** `tail` keeps only lines with a given text or from a given level up, and `get_errors` only errors with a given text.
- **Documentation.** The mise environment page explains why a `mise.toml` in a package folder of a monorepo does not reach a session, and the dev container guide shows how to bring skills and plugins into the container.

## Moving from 0.5.11

Click "Update and restart" (or "Update after their turn" while agents work) when Trackwall offers 0.5.12, or install it by hand ([Update by hand](https://jakubprill.github.io/trackwall/guide/install#update)). Your data in `~/.trackwall` stays, and the sessions that were running come back after the restart. If you skip 0.5.11, take the two one-time steps from its release note: "Push to this remote" in "Settings > Workspace" for a local config store with a remote, and pointing antivirus or backup rules at the new `.trackwall` folder.

## Known limitations

- Sessions run Copilot CLI only, and it has to be installed and signed in.
- The app is not signed: on Windows download it with `gh` or `curl.exe`, or run `Unblock-File` on the zip; on macOS remove the quarantine with `xattr`.
- A proxy that signs you in with your Windows account or replaces certificates can stop the update download; the manual update still works then.
- macOS on Apple Silicon only.
