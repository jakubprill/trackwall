Trackwall 0.5.16 fixes the desktop app losing Trackwall in a dev container while it is still running.

## Fixed

- **The app keeps Trackwall in a container on a slow port forward.** VS Code's port forward starts a program for every new connection, which can take a few seconds on a busy computer or one whose security software checks every program that starts. The desktop app now waits up to 10 seconds for Trackwall in a container before it says it lost the connection; Trackwall started by the app itself keeps the short limit. See [Dev container](https://jakubprill.github.io/trackwall/guide/dev-container).

## Moving from 0.5.15

Click "Update and restart" (or "Update after their turn" while agents work) when Trackwall offers 0.5.16, or install it by hand ([Update by hand](https://jakubprill.github.io/trackwall/guide/install#update)). Your data in `~/.trackwall` stays, and the sessions that were running come back after the restart. If you skipped 0.5.15, read its "Before you start" about the sandbox on Linux.

## Known limitations

- Sessions run Copilot CLI only, and it has to be installed and signed in.
- The app is not signed: on Windows download it with `gh` or `curl.exe`, or run `Unblock-File` on the zip; on macOS remove the quarantine with `xattr`.
- A proxy that signs you in with your Windows account or replaces certificates can stop the update download; the manual update still works then.
- macOS on Apple Silicon only.
- Chat (preview) has no Java navigation for tasks, and a running task cannot switch between the terminal and Chat.
